# Barstone — סטודיו ההדמיות

אפליקציית ווב לאנשי המכירות: לקוח › הזמנה › סטודיו חי במסך אחד (שרטוט, תלת־ממד ונסטינג על לוחות 320×160) › מסמך ללקוח.

## מה יש
- **לקוחות והזמנות** שמורים ב-Supabase, עם התחברות והרשאות צוות. שמירה אוטומטית.
- **שלוש דרכים לפתוח הזמנה**: תבנית (ישר / L / U / אי), קובץ **DXF** של מדידה, או **צילום תוכנית** (AI).
- **סטודיו**: גרירת חלקים ופתחים, שינוי מידות על השרטוט, ביטול/חזרה (Ctrl+Z), תלת־ממד חי עם הגיד האמיתי מהלוח, ייצוא תמונת 4K וייצוא נסטינג ל-DXF.
- **בודק חכם**: חיבור שעובר בפתח, פתח קרוב לקצה, כיור מול כיריים, חלק שלא נכנס בלוח, הצעות עיצוב — עם תיקון בלחיצה.
- **עריכה בשפה חופשית וחוות דעת מקצועית** (AI).

## מבנה
- `src/core/` — הליבה, בלי תלות בדפדפן: `model.ts` (מודל המטבח האחיד, מ"מ), `nesting.ts`, `dxf.ts`, `checks.ts`.
- `src/ui/` — המסכים (React). `src/store.ts` — מצב, היסטוריה ושמירה. `src/data/repo.ts` — Supabase / מצב הדגמה מקומי.
- `supabase/migrations/` — סכמה. `supabase/functions/ai/` — פונקציית הקצה של ה-AI.
- `tests/` — בדיקות לליבה. `legacy/` — המערכת הקודמת, לעיון בלבד (לא נפרסת).

## הרצה
```bash
npm install
npm run dev      # http://localhost:3000 — מצב הדגמה מקומי, בלי התחברות
npm test
npm run build    # בנייה לפריסה, מחוברת ל-Supabase (.env.production)
```

## פריסה
`render.yaml` מגדיר Static Site ב-Render (בנייה: `npm ci && npm run build`, תיקייה: `dist`).
ב-`.env.production` יש רק את כתובת הפרויקט והמפתח הציבורי (publishable) — אין בו סודות.

## התחברות והרשאות
המשתמש הראשון שנרשם ומאשר את האימייל הופך למנהל. מאותו רגע רק אימיילים שהמנהל הוסיף במסך "צוות" מקבלים גישה; כל השאר רואים "ממתין לאישור".

## הפעלת ה-AI
ב-Supabase › Edge Functions › Secrets מוסיפים `ANTHROPIC_API_KEY`. בלי המפתח שאר המערכת עובדת כרגיל, וכפתורי ה-AI מחזירים הודעה ברורה.
